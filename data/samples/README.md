# Sample documents

These files are loaded by `npm run ingest` (or the **Load sample docs** button in the UI).
They cover four file formats and three kinds of content: internal company documents that
are not on the web, a public technical standard, and a protocol specification.

| File | Format | What it is | Source / license |
|---|---|---|---|
| `northwind-employee-handbook.pdf` | PDF (4 pages, includes a table) | HR handbook of a **fictional** company: hybrid work, PTO, 401(k), travel, reviews | Written for this project, MIT (generated by `scripts/prepare_samples.py`) |
| `northwind-security-policy.docx` | DOCX | IT security policy of the same fictional company: MFA, passwords, patching, incident response | Written for this project, MIT (generated by `scripts/prepare_samples.py`) |
| `pep-0008-style-guide.rst` | reStructuredText | PEP 8, the Python style guide | [python/peps](https://github.com/python/peps/blob/main/peps/pep-0008.rst), public domain |
| `mcp-specification-2026-07-28.md` | Markdown | Overview, changelog, architecture, transports and tools pages of the MCP spec, revision 2026-07-28 | [modelcontextprotocol/modelcontextprotocol](https://github.com/modelcontextprotocol/modelcontextprotocol) @ `bbc31f8`, Apache-2.0 (some older parts MIT); MDX converted to Markdown |

Why this mix: the Northwind documents contain facts that a web search cannot find, so they
show what RAG adds. Several of their policies point to outside facts that change over time
(for example "reimbursed at the current IRS mileage rate"), which is where the hybrid
docs + web route is useful.

To regenerate the files:

```bash
pip install reportlab python-docx
python scripts/prepare_samples.py
```

The evaluation questions for these documents are in [`../eval/questions.jsonl`](../eval/questions.jsonl).
